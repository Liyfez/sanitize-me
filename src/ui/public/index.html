Frequently asked questions

Does sanitize-me re-encode images or reduce resolution?

No. sanitize-me performs byte-level binary stripping directly on JPEG APP1 segments, PNG ancillary chunks, and WebP RIFF containers. Pixel data is 100% untouched without compression loss.

How does sanitize-me prevent PDF corruption?

PDF documents require byte-offset cross-reference tables (xref). sanitize-me zeroes out /Info keys and /Metadata streams with space-padding, preserving exact byte positions.

How does sanitize-me neutralize XSS payloads without dependencies?

It uses recursive multi-pass elimination to destroy nested evasion tags (like <scr<script>ipt>), enforces a strict element whitelist, strips inline on* event handlers, and blocks dangerous URI schemes (javascript:, data:text/html).

How does sanitize-me protect NoSQL and MongoDB queries?

It recursively traverses incoming JSON objects and removes or neutralizes any key starting with '$' ($gt, $ne, $where) or containing dot-notation traversal, neutralizing NoSQL injection attacks.

Can sanitize-me run offline in air-gapped environments?

Yes. sanitize-me has zero third-party dependencies and uses only standard Node.js libraries. The web airlock executes entirely within local browser memory.

What credentials and data are redacted before sharing?

API keys, secret tokens, private keys, JWTs, auth headers, IPv4/IPv6 addresses, personal emails, local file paths, and Luhn-validated credit card numbers.
